梯度提升树如何给曝光打分

以 KuaiRand-1K 上训练的 click 模型（运行 20261014_153646_b1_lgbm_f1_is_click）为例，所有数字取自该模型和同一条真实样本

摘要　LightGBM 是梯度提升决策树（GBDT）的一种实现。模型把 84 维特征向量 x 送进 407 棵回归树，把每棵树落到的叶子值相加得到分数 F(x)，再经 sigmoid 变成点击概率 p。训练是一个迭代过程：第 m 轮先用当前模型算出每条样本的概率，再把概率与真实标签的差（梯度）当作新目标，长一棵树去拟合它，乘以 0.05 的学习率加到模型上；验证集 AUC 连续 50 轮不再上升就停止。本文用总览图说明输入输出，用机制图说明一轮迭代、直方图分桶与 leaf-wise 生长，然后解剖真实模型的第一棵树和一条样本的 407 步预测轨迹，最后用 6 条样本、3 棵桩树的玩具例子把公式算一遍。

1总览：一个向量进去，一个概率出来

输入是一次曝光的 84 个数（上下文、用户静态、视频静态、滚动统计四组，见上一篇"一条曝光的 84 维输入"），缺失记为 NaN。输出是一个 0 到 1 之间的数 p，含义是"这次曝光会被点击的概率"。模型本体是 407 棵树的加法：

F(x) = f1(x) + f2(x) + … + f407(x)　　p = σ(F(x)) = 1 / (1 + e−F(x))

2目标函数：从 LogLoss 到两个梯度

二分类用的是对数损失。对 N 条曝光：

L = −(1/N) Σi [ yi ln pi + (1 − yi) ln(1 − pi) ]，　pi = σ(F(xi))

梯度提升不直接对 F 求解，而是问：如果给每条样本的分数 F(xi) 加一个小量，损失会怎么变？答案由一阶导 g 和二阶导 h 给出，对 LogLoss 两者形式都极简单：

gi = ∂Li/∂F = pi − yi　　hi = ∂²Li/∂F² = pi(1 − pi)

g 是"预测比真实高了多少"：点了却只给 0.2 的样本 g = −0.8，没点却给 0.9 的样本 g = +0.9。h 是不确定度，p 接近 0.5 时最大。新树的任务是在每个叶子里给出一个常数 w，让叶子内样本的损失下降最多。对叶子 j 做二阶展开并求最小，得到 LightGBM 真正写进模型文件的叶子值和分裂时比较用的增益：

wj = − Gj / (Hj + λ)，　Gj = Σi∈j gi，Hj = Σi∈j hi　　λ = lambda_l2 = 1
gain(split) = GL²/(HL+λ) + GR²/(HR+λ) − G²/(H+λ)

直观地读：叶子里的样本整体被高估（G > 0），叶子值就是负的，把它们往下拉；样本越多、h 越大，拉得越稳。λ 在分母上，样本少的叶子会被压向 0，这是防过拟合的第一道闸。

4直方图分桶与 leaf-wise 生长

找最佳切分本来要对每个特征的每个取值都试一遍，502 万行乘 84 列做不到。LightGBM 的两个核心取舍把它变成了可行的：

直方图：建 Dataset 时把每个连续特征按分位数切成至多 255 个桶（这就是 1.7 GB 的 float32 矩阵变成 0.4 GB 的原因，每个值只存 1 字节桶号）。之后找切分只需在 255 个桶边界上比较增益，而 G、H 的累加对每个叶子只做一遍，子叶子的直方图还能用"父减兄"得到。

leaf-wise：传统做法按层生长，同一层所有叶子一起分裂。LightGBM 每次只分裂当前增益最大的那一个叶子，同样 127 个叶子能得到更低的损失，代价是树可能很深很偏（这个模型里深度 10 到 31），所以必须配合 min_data_in_leaf 和 λ 防止在小样本上钻牛角尖。

5类别特征、缺失值与我们用的参数

类别特征（tab、tag_first、upload_type、18 个 onehot 等 26 列）不按大小切分。LightGBM 把一个类别特征的各取值按 G/H 排序，然后在排好的序列上找最优的"左右两堆"，所以切分长成"tag_first ∈ {1, 2, 5, 8, 14, …}"这样的集合（图 4 里就有一个）。类别编码里的 −1（缺失）被当成 NaN。

缺失值（NaN）不需要填补：每个分裂节点学一个默认方向，缺失样本统一走那边。图 4 里 user_gap_s 的节点 default_left = false，意味着"没有上一次请求"的样本走右边。

8一个能手算的例子：6 条曝光，3 棵桩树

同一个用户的 6 条曝光，只有两个特征：作者历史点击率 a 和视频时长 d（秒）。用只有一次分裂的树（桩），λ = 1，学习率 0.3，走三轮。初始模型是常数 ln(3/3) = 0，所有人 p = 0.5。

手算第 1 轮

p = 0.5 时每条样本 h = 0.25，g = +0.5（y = 0）或 −0.5（y = 1）。切分 a ≤ 0.675 的左侧有三个 +0.5 和一个 −0.5，GL = 1.0，HL = 1.0，叶子值 wL = −1.0 / (1.0 + 1) = −0.500；右侧 GR = −1.0，HR = 0.5，wR = 1.0 / 1.5 = +0.667。增益 = 1.0²/2 + 1.0²/1.5 − 0²/2.5 = 1.167，比在 d 上任何切分都大。乘学习率 0.3 后左侧 F = −0.150，p = 0.463；右侧 F = +0.200，p = 0.550。第 2 轮用新的 p 重新算 g、h，再来一遍。

9为什么它适合这份数据，以及边界

这份数据的三个特点正好落在 GBDT 的长处上。第一，特征是异构的表格：类别、计数、比率、缺失混在一起，树模型不需要归一化、分桶或独热。第二，test 里 85% 的视频在训练集没出现过，靠 id 记忆的方法失效，而树只用泛化特征和历史统计。第三，502 万行、84 列在 16 线程上三分钟一个模型，一天能做十几组消融。

边界也清楚。树给出的是分段常数函数，对"用户历史序列"这种结构没有表达能力，只能通过我们预先聚合的统计量看到它；用户 × 作者、用户 × 类目这些交叉也要靠人工枚举 key 才能进模型。图 5b 还提醒一件事：分数主要来自用户级的基率特征，这在用户内排序时没有贡献。Day 2 的深度模型要回答的正是这两个问题：让模型自己学交叉，以及把序列直接喂进去。
