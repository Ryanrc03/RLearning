# A/B Test 与 p-value

## 一句话

**A/B test 把用户随机分成 control 和 treatment 两组，只有一处不同，比较两组的指标；p-value 是「假设两组其实没区别」时看到这么大差异的概率，小于 0.05 才说差异显著。**

它是离线指标和线上收益之间唯一可靠的桥。

## 为什么需要它

离线 AUC 从 0.80 涨到 0.81，不等于线上点击率会涨。离线数据是旧模型挑出来的，新模型换一批内容，用户行为会跟着变；指标之间还可能打架，点击涨了停留时长掉。唯一的办法是真拿一部分流量试。

但两组用户的转化率本来就会因为抽样而不同：同一个模型随机分两组，10.0% 对 10.3% 的差很常见。p-value 就是用来回答「这个差是运气还是真的」。笔记里的记法：p = 0.05 意味着就算 A 和 B 是同一种药，也有 5% 的机会看到这么大的差。

## 怎么工作

<AbTestFigure />

笔记里的四步，对应图右边的四张卡片：

1. **分组**：随机把用户分成 control（A，现状）和 treatment（B，改动），除了这一处改动，两组什么都一样。
2. **Power analysis**：开跑之前先算要多少样本。想以 80% 的把握测出 1 个百分点的提升，每组大约要几千人；样本不够，真有效果也看不出来。
3. **执行**：跑够样本再看结果，中途不停。
4. **假设检验**：假设两组没区别（零假设），算观测到的差有多不寻常。两组比例用 z 检验：

$$
z = \frac{\hat p_B - \hat p_A}{\sqrt{\bar p\,(1 - \bar p)\left(\frac{1}{n_A} + \frac{1}{n_B}\right)}},\qquad
p = 2\,\big(1 - \Phi(|z|)\big)
$$

图里两条曲线是「每组抽 n 个人时，观测到的转化率会落在哪」。样本量小，两条曲线大面积重叠，抽到的两个值谁高谁低全看运气；样本量大，曲线变窄分开，差异才稳定地显出来。切到「其实没区别」再多拖几次样本量，偶尔也会撞上 p < 0.05，这就是那 5%。

## 代价与取舍

- p < 0.05 不是「B 有 95% 的概率更好」，而是「没区别时有 5% 的机会看到这么大的差」。它说的是数据在零假设下有多不寻常，不是 B 多好。
- 样本不够时真效果也测不出来（power 低）；样本太多时芝麻大的差也显著，所以要同时看效应大小，不只看 p。
- 偷看：每天看一眼 p-value、一显著就停，会把 5% 的误判率抬高好几倍。先定样本量，跑够再看。
- 分组要真随机，而且按用户分而不是按请求分，否则同一个人会看到两种版本。两组之间也不能互相影响，比如社交产品里 B 组用户发的内容 A 组也会看到。
- 实验多了以后，每个人各自在 Notebook 里算 p-value 会算出不一样的结果。把取数、清洗和检验固定成一个平台的例子，见[从 Excel + Notebook 到 A/B 实验分析平台](/notes/systems/design/ab-testing-analytics-platform/)。
