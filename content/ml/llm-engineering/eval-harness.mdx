# Eval Harness 与数据飞轮

## 一句话

**Eval harness 是生成之后的一道自动关卡：规则检查在前，规则判不了的交给模型门控，不合格就自动重生成；判过的样本再回流成下一轮的训练数据。**

网页、海报、代码这类能被检查的产出都适合；它把上一页的抽样评估变成每次生成都跑的流水线。

## 为什么需要它

GSB 能说明新模型整体更好，但它是离线抽样做的；线上每次生成的这一份能不能交付，等不了人来判。模型一次生成的网页大约 60% 是好的，剩下的有文字溢出、字段缺失这种硬伤，也有排版难看、内容跑题这种软毛病。直接交付，四成坏页面落到用户手里；全靠人工复核，又贵又慢。

## 怎么工作

<EvalHarnessFigure />

$$
P(\text{K 次重试内通过}) = 1 - (1 - a)^{K+1},\qquad \mathbb{E}[\text{生成次数}] = \frac{1 - (1 - a)^{K+1}}{a}
$$

$$
\text{优质率} = \big(1 - (1 - a)^{K+1}\big)\cdot \text{precision} + (1 - a)^{K+1}\cdot P(\text{好} \mid \text{被拒})
$$

**分层。** 第一层是确定性检查：渲染后量文本框有没有溢出，JSON 能不能 parse，必填字段在不在。几乎不要钱、可复现、不误杀，25% 的硬伤全在这层拦下。第二层是 VLM 质量门：截图交给多模态模型按 rubric 判排版和内容；每次调用 0.3 次生成的成本，还会误杀 5% 的好页面。规则在前，VLM 只需看 75% 的页面；切到「只有 VLM」，每次都要付 VLM 的钱，它对像素级溢出只抓到六成，坏页面混进「通过」，优质率封顶 81.4%。

**重试有天花板。** 一次通过率 $a = 60\%$，每次重生成是独立的抽样。不重试时门控挑出了坏页面却没有替代品，优质率还是 60%；最多重试 2 次到 89.4%，平均只生成 1.56 次。再往后收益递减（3 次 92.8%，5 次 94.6%），上限是门控的 precision 95%：门控放过的坏页面重试多少次都救不回来。每张好页面的成本从 2.06 涨到 2.16 就不动了；「没有门控」的 1.67 看似最便宜，是把坏页面的代价转嫁给了用户。

**数据飞轮。** 门控每天都在产出带标签的数据：过关的是正样本，被拒的连同理由是负样本。飞轮是线上日志 → 标注 → SFT → eval → 上线 → 新的日志。标注最贵，先让 role-play 的 LLM 扮演挑剔的设计师或目标用户按 rubric 自动标，人只抽检它拿不准的；自动标掉四成，人工就少四成。另一半工作是修评估本身：规则会误报（把故意的省略号当溢出），VLM 门控会和人工漂移，要定期用人工标注对一遍，把误杀和漏放的样本改写成新规则或 rubric 条目。

## 代价与取舍

- 重试不免费：延迟随生成次数涨，尾部更糟。实时交互重试一两次就停，后台批量可以多给几次。
- 重试救不了系统性错误：某类 prompt 每次都溢出，重试只是多付几次钱。要从失败日志里找出它们，改 prompt 或改模型。
- 门控会被优化：用门控挑的数据训 SFT，模型会学会讨好门控而不是变好。评估集要和训练数据隔开，门控要定期用人工 GSB 校准。
- 自动标注的偏差会被放大：role-play 标注员的偏好会被 SFT 学进去。要分层抽检，和人工一致率不够就别用。
- 说「优质率 60% → 90%」时要讲清分母是全部交付还是只算过关的、「好」是谁判的。
