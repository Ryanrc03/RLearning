# LLM-as-judge 与 GSB

## 一句话

**开放式生成没有标准答案，就把新旧两个模型的回答并排放好，让人或大模型判新的那个 Good / Same / Bad，再把 G、S、B 的个数算成胜率。**

模型迭代、prompt 改版、上线前的评估都靠它；大模型当评委能省掉大部分人工，前提是先校准它自己的偏差。

## 为什么需要它

上一页改了 prompt、降了温，怎么知道新版本真的更好？分类有标签，Precision、Recall 一算就清楚；写文案、做网页没有唯一正确答案。给单个回答打 1–10 分也不稳，同一个人隔天打分都会飘。人更擅长比较：两份并排放着，哪份更好一眼能判。GSB 把「比」变成数字；请人比又慢又贵，于是让大模型当评委，评委的偏差就成了新问题。

## 怎么工作

<LlmJudgeFigure />

$$
\text{net} = \frac{G - B}{G + S + B},\qquad \text{win rate} = \frac{G}{G + B}
$$

$$
p = 2 \sum_{i=\max(G,\,B)}^{n} \binom{n}{i}\, 2^{-n},\qquad n = G + B
$$

**两种胜率。** 同样是 $G/(G+B) = 80\%$，可能是 40 / 50 / 10（net +0.30），也可能是 8 / 90 / 2（net +0.06）：后者九成的 prompt 根本没区别。所以报胜率要说清是哪个公式，最好两个都报，再报 S 的占比。图里「新模型确实更好」的人工标注是 72 / 35 / 13：胜率 84.7%，net +0.49。

**位置偏差。** 评委会给先读到的回答多加一点分。新模型坐 A 位，胜率被抬到 95.0%；坐 B 位只剩 63.3%。切到「两个模型一样好」更明显：人工 36 比 33 打平，评委却给出 73.8%、sign test p < 0.001，一个完全由座位造成的「显著提升」。同类的还有长度偏差（越长越像好答案）和自我偏好（偏爱自己家族模型写的）。

**怎么消。** 每对判两次、A/B 互换，两次的偏好分取平均（离散判决的保守版本是不一致就记 Same），位置项正好抵消：一样好的回到 56.3%、p = 0.34，不显著；更好的 83.5%，和人工的 84.7% 只差一个点。再写一份 rubric，说清准确、完整、格式各看什么、长度不加分；留一小批人工标注定期算一致率，够高才让评委替人。

**是不是运气。** S 不带方向信息，把非平局的 G 和 B 当抛硬币：没区别时每个都是一半概率，这就是 sign test，和 A/B test 问的是同一个问题。8 比 2 也是 80%，但 p ≈ 0.11；80 比 20 的 p 小于 $10^{-8}$。说「胜率 80%」之前先报 n，图里每个分数旁边都给了 95% 置信区间。

## 代价与取舍

- 交换顺序判两次，评委成本翻倍；不交换，位置偏差会原样进入胜率，省下的钱买到的是一个错的结论。
- 先定口径：$G/(G+B)$ 好看但藏住了平局，$(G-B)/N$ 保守但能看出「大部分没变」。被问到「GSB 胜率 80%」时，要能答出公式、n、S 占多少、评委和人工的一致率。
- 评委不是真值。一致率只有六七成时，它能看大方向，判不了一两个点的差。rubric 没写「长度不加分」，评委会稳定地偏向啰嗦的回答，这种偏差交换顺序消不掉。
- 自我偏好：同一家族的模型既当选手又当评委，最好换评委，或者多个评委投票。
- 线下 GSB 赢了不等于线上赢，最后还要用 A/B test 拿真实用户行为验证。
