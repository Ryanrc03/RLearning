# 梯度提升树如何给曝光打分

上一篇把一次曝光变成了 84 个数。这篇看这 84 个数进入模型之后发生了什么。例子是 kuairank 里在 KuaiRand-1K 上真实训练的 LightGBM click 模型（运行 `20261014_153646_b1_lgbm_f1_is_click`）：所有数字都取自这个模型和同一条样本，没有示意值。

## What is it?

LightGBM 是梯度提升决策树（GBDT）的一种实现。模型不是一棵大树，而是 **407 棵小回归树的加法**：向量 `x` 走完每棵树，各落到一个叶子，把叶子值相加得到分数 `F(x)`，再经 sigmoid 变成点击概率。

```text
F(x) = f_1(x) + f_2(x) + … + f_407(x)
p    = σ(F(x)) = 1 / (1 + e^(−F(x)))
```

对那条样本，第一棵树给 −0.437（它包含了初始分：训练集点击率 0.3806 的对数几率 −0.487），之后每棵树只做小幅修正，最后 `F = 0.196`，`p = 0.549`，而真实标签是 0。

## Why gradients?

二分类用对数损失（LogLoss）：

```text
L = −(1/N) Σ_i [ y_i ln p_i + (1 − y_i) ln(1 − p_i) ],   p_i = σ(F(x_i))
```

梯度提升不直接求解 `F`，而是问：**给每条样本的分数加一个小量，损失会怎么变？** 答案由一阶导 `g` 和二阶导 `h` 给出，对 LogLoss 两者都很简单：

```text
g_i = ∂L_i/∂F  = p_i − y_i        "预测比真实高了多少"
h_i = ∂²L_i/∂F² = p_i (1 − p_i)   不确定度，p 接近 0.5 时最大
```

点了却只给 0.2 的样本 `g = −0.8`；没点却给 0.9 的样本 `g = +0.9`。新树的任务是在每个叶子里给一个常数 `w`，让叶子内样本的损失下降最多。对叶子做二阶展开并求最小，就得到 LightGBM 真正写进模型文件的叶子值，以及分裂时比较用的增益：

```text
w_j = − G_j / (H_j + λ),   G_j = Σ_{i∈j} g_i,  H_j = Σ_{i∈j} h_i,  λ = lambda_l2 = 1
gain(split) = G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ)
```

直观地读：叶子里的样本整体被高估（`G > 0`），叶子值就是负的，把它们往下拉；样本越多、`h` 越大，拉得越稳。`λ` 在分母上，样本少的叶子被压向 0——这是防过拟合的第一道闸。

## How does one round work?

训练就是把一个环转 407 圈。第 0 圈的模型是常数：训练集点击率的对数几率 `ln(0.3806 / 0.6194) = −0.487`。之后每一轮：

1. 用当前模型算每条样本的 `p`，得到 `g`、`h`。
2. 长一棵树去拟合这组梯度（不是标签 `y`），叶子值按上面的公式。
3. 乘学习率 0.05，加到模型上。
4. 在验证集上算 AUC；连续 50 轮不再上升就停。这个模型停在第 407 轮。

关键是第 2 步：每棵新树拟合的是**前面所有树留下的共同残差**，所以树之间不是独立的，顺序有意义。

## Histograms and leaf-wise growth

找最佳切分本来要对每个特征的每个取值都试一遍，502 万行乘 84 列做不到。LightGBM 的两个取舍让它变得可行：

- **直方图。** 建 Dataset 时把每个连续特征按分位数切成至多 255 个桶，每个值只存 1 字节桶号（1.7 GB 的 float32 矩阵因此变成 0.4 GB）。找切分只需在桶边界上比较增益；`G`、`H` 对每个叶子只累加一遍，子叶子的直方图还能用"父减兄"得到。
- **leaf-wise 生长。** 传统做法按层生长，同一层所有叶子一起分裂。LightGBM 每次只分裂当前增益最大的那一个叶子，同样 127 个叶子能换来更低的损失；代价是树可能很深很偏（这个模型里深度 10 到 31），必须配合 `min_data_in_leaf` 和 `λ` 防止在小样本上钻牛角尖。

## Categorical features and missing values

26 个类别特征不按大小切分。LightGBM 把一个类别特征的各取值按 `G/H` 排序，在排好的序列上找最优的"左右两堆"，所以切分长成 `tag_first ∈ {1, 2, 5, 8, 14, …}` 这样的集合；类别编码里的 −1 被当成缺失。

缺失值不需要填补：每个分裂节点学一个**默认方向**，缺失样本统一走那边。第一棵树里 `user_gap_s` 的节点 `default_left = false`，意思是"没有上一次请求"的样本走右边。

## The parameters this model used

| 参数 | 值 | 作用 |
| --- | --- | --- |
| objective | binary | LogLoss，输出经 sigmoid |
| num_leaves | 127 | 每棵树的叶子数，leaf-wise 的容量上限 |
| min_data_in_leaf | 200 | 叶子至少 200 行，阻止在小群体上过拟合 |
| learning_rate | 0.05 | 每棵树的贡献乘 0.05；越小越稳，需要的树越多 |
| feature_fraction | 0.8 | 每棵树随机只看 80% 的列 |
| bagging_fraction / freq | 0.8 / 1 | 每棵树随机只用 80% 的行 |
| lambda_l2 | 1.0 | 叶子值分母里的 λ |
| max_bin | 255 | 直方图桶数 |
| num_rounds / early_stopping | 2000 / 50 | 上限与早停耐心；实际停在 407 |
| num_threads | 16 | 训练 159 秒 |

两处值得停下来看：

- **第一棵树**的根节点和两个子节点都在切 `utab_ctr_all`（用户在该 tab 的历史点击率），与特征重要性里它排第一一致：在没有其它信息时，"这个人在这个场景平时点多少"是最有用的一刀。
- **407 步轨迹**：第 1 棵树后 `p = 0.392`，前 115 棵树一路抬到 0.594，之后两百多棵树缓慢往下修到 0.549。把最终的 `F = 0.196` 按特征拆开（SHAP 式的 pred_contrib），两个"用户历史率"特征就贡献了 +0.82，其余 70 个特征合计只有 +0.03。模型给的 0.549 本质上是"这个人平时就爱点"，而不是"这个视频有多好"——这也是它在随机集上高估的来源。

## Why it fits this data, and where it stops

这份数据的三个特点正好落在 GBDT 的长处上：特征是异构的表格（类别、计数、比率、缺失混在一起，不需要归一化或独热）；test 里 85% 的视频在训练集没出现过，靠 id 记忆的方法失效，而树只用泛化特征和历史统计；502 万行、84 列在 16 线程上三分钟一个模型，一天能做十几组消融。

边界也清楚：

- 树给出的是**分段常数函数**，对"用户历史序列"这种结构没有表达能力，只能通过预先聚合的统计量看到它。
- 用户 × 作者、用户 × 类目这类交叉要靠人工枚举 key 才能进模型。
- 分数主要来自用户级的基率特征，这在**用户内排序**时没有贡献。

让模型自己学交叉、把序列直接喂进去，是深度排序模型要回答的问题。

## Key ideas to remember

1. 模型是 407 棵树的**加法**，每棵树只在它被创建的那一轮学一次。
2. 树拟合的是梯度 `p − y`，不是标签；二阶导 `h` 决定步子多稳。
3. 叶子值 `−G/(H+λ)` 和增益公式是整个算法的核心，`λ` 是第一道防过拟合的闸。
4. 直方图和 leaf-wise 是工程取舍：前者换速度，后者换损失，代价是树更偏。
5. 看一条样本的贡献拆解，比看全局特征重要性更能说明模型"为什么这样打分"。
