# RNN：hidden state 一步一步传

## 一句话

**RNN 用一个固定长度的 hidden state h 把读过的东西压起来，每读一个 token 就按 $h_t = \tanh(W_{hh} h_{t-1} + W_{xh} x_t)$ 更新一次，同一套权重沿时间轴反复用。**

它是 Transformer 之前处理文本、语音、时间序列的标准模型，LSTM 和 GRU 都是在这个骨架上加门。

## 为什么需要它

[前面几章](/notes/ml/dl-blocks/normalization/) 的模型吃的都是定长的向量：一个样本进去，一个预测出来。一句话却是一串长短不一的 token，硬把它拼成一个大向量，既要定死最长长度，又要让第 3 个词和第 30 个词各学一套权重，词换个位置就不认识了。RNN 换一种读法：不一次吃整句，而是一个 token 一个 token 地读，每读一个就把 hidden state 更新一次。权重只有一套，序列多长都用它，h 的长度也不随序列变，读完最后一个 token 时 h 里就是整句的摘要。

## 怎么工作

<RnnFigure />

$$
h_t = \tanh\left(W_{hh}\,h_{t-1} + W_{xh}\,x_t\right),\qquad h_0 = 0
$$

$$
y_t = \mathrm{softmax}\left(W_{hy}\,h_t\right)
$$

图里是一个缩到能手算的 RNN：输入 2 维、hidden 3 维、3 个输出类，权重固定，10 个输入由固定种子生成。每按一次「下一步」就读入一个 x_t，格子里的三根 bar 是新的 h_t；下面的面板把这一步的每一项都列出来：W_xh x_t 是当前输入的贡献，W_hh $h_{t-1}$ 是上一步状态的贡献，两项相加过 tanh 就是 h_t，再过 W_hy 和 softmax 得到这一步的输出 y_t。

第 1 步没有过去，h₀ 是零向量，W_hh h₀ 也全是零，h₁ 只由 x₁ 决定。从第 2 步起橙色箭头开始起作用：$h_{t-1}$ 不是被丢掉，而是乘上 W_hh 再加进来，所以 x₁ 的信息经过 h₁、h₂、h₃ 一路传下去，只是每传一次就要再过一遍 W_hh 和 tanh，到后面越来越淡。读完 10 步，h₁₀ 这三个数就是模型对整句的全部记忆。

右边的形状面板是笔记里那组真实尺寸：batch 32 条序列、每条 10 步、每步 50 维输入，所以输入是 (32, 10, 50)；hidden_size 100，每一步都留下一个 h_t，叠起来是 (32, 10, 100)；输出每步一个，也是 (32, 10, 100)。三个轴分别是「哪条序列、第几步、这一步的向量多长」，图里的版本只是把后两个维度缩成了 2 和 3。

## 代价与取舍

- h_t 要等 $h_{t-1}$ 算完才能开始，10 个 token 就是 10 轮顺序计算，GPU 再多核也只能在 batch 维度并行，这是下一页的主题。
- 整句被压进一个固定长度的 h 里，早先的输入要穿过很多次 W_hh 和 tanh 才能影响到后面，梯度也沿同一条链往回传，很容易消失或爆炸；LSTM、GRU 加门就是为了让信息能跳过几步直接传。
- 同一套权重反复用意味着参数量不随序列长度增长，这是优点；但也意味着第 1 步和第 100 步用的是完全一样的变换，模型分不清位置，只能靠 h 里的内容间接记。
- 推理时它很省：每生成一个 token 只需更新一个固定大小的 h，不用回头看整句。线性递归模型（Mamba 一类）想重新拿回的就是这个优势。
