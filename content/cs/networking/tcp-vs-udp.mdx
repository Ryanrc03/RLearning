# TCP vs UDP

## 一句话

**TCP 保证每个包都送到、按顺序交付，丢了就重发，所以什么时候到说不准；UDP 发了就不管，丢了就丢，但每个包要么很快到、要么不到。**

文件、网页、聊天记录这种少一个字节就坏的数据用 TCP。视频通话、游戏位置、传感器帧这种“旧的没用、要最新的”数据用 UDP。

## 一张图

<TcpVsUdpDiagram />

| | TCP | UDP |
| --- | --- | --- |
| 丢了一个包 | 重传，后面的包攒着等它 | 丢了就丢，后面的照常交付 |
| 50 ms 后 | 补上了，但整批都过期 | 新的帧已经到了 |

所以 TCP 换来的是**完整**，UDP 换来的是**及时**，一个包丢了之后两者只能选一个。

## 一个真实的例子：视频通话卡一下

微信视频通话偶尔画面跳一下，跳过去就接着放，不会倒回去补那半秒。因为通话走 UDP：丢掉的那几帧补回来也已经过时了，不如直接显示最新的。

同一个微信发文件走 TCP：文件少一个包就打不开，宁可多等一会儿也要把每一块都收齐。车上的雷达帧和视频通话是一类，日志回传和发文件是一类。
