# HTTP vs gRPC

## 一句话

**HTTP 是浏览器和服务器说话的通用格式，文本头部，每次请求都要自我介绍一遍；gRPC 是让调远程函数像调本地函数，底下是 HTTP/2 加 Protobuf，头部压缩、一条连接同时跑很多个调用。**

对外给浏览器和第三方用的接口走 HTTP 加 JSON，谁都能接。服务和服务之间、app 和后端之间的大量小调用走 gRPC。

## 一张图

<HttpVsGrpcDiagram />

| | HTTP/1.1 + JSON | gRPC |
| --- | --- | --- |
| 发 1 次 | 272 字节，头比正文大 | 45 字节 |
| 发 100 次 | 27 KB，一条连接一次排一个，17 个来回 | 4.5 KB，100 个一起飞，1 个来回 |

所以 HTTP 换来的是**通用**，gRPC 换来的是**多次小调用时又小又快**。一次调用看不出差别，一百次才看得出。

## 一个真实的例子：外卖 app 刷一次首页

打开外卖 app 首页，手机要向后端要位置、推荐、优惠券、购物车、公告，几十个小请求。后端收到以后，又要在十几个微服务之间互相调用。这些调用每个只有几十字节正文，如果每次都带 200 字节的文本头、一次排一个，首页就要转好几秒。

所以 app 和后端之间、微服务之间用 gRPC：头部压缩，一条连接同时跑几十个调用，一个来回全回来。你在浏览器里打开的网页版，对外那一层还是 HTTP，因为浏览器只会说 HTTP。
