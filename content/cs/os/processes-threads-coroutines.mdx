# 进程、线程、协程，以及 CUDA 里的“线程”

四个词说的是同一件事：让一台机器同时推进几件工作。它们的差别只在三个问题上：**谁决定下一个跑谁，切换一次多贵，一个任务出事连累谁。** 贯穿全文的例子是车上的感知管线：多路 camera 每秒送来几十帧图像，要解码、预处理、送 GPU 推理，同时写日志。

## What are they?

| | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 内存 | 独立地址空间 | 共享地址空间，各有一个栈 | 共享一个线程，各有一个小帧 |
| 谁调度 | 内核 | 内核 | 用户态事件循环 |
| 怎么切换 | 抢占，换页表 | 抢占，换寄存器和栈 | 主动让出（`await`） |
| 一个崩了 | 只死自己 | 整个进程死 | 整个进程死 |
| 多核 | 能 | 能 | 单个事件循环不能 |

- **进程**是操作系统分配资源的单位：地址空间、文件描述符、信号处理都是它的。
- **线程**是操作系统调度的单位：同一进程的线程共享代码和堆，只有栈和寄存器是自己的。
- **协程**内核看不见：它是一个能中途暂停、之后从暂停处继续的函数，由用户态的调度器在几千个协程之间切换。

## Thread vs. process

一句话：**进程是资源的容器，线程是执行的单位。** 小白向的解释、对比图和 Chrome 的例子在单独一页：[Process vs Thread](/notes/cs/fundamentals/process-vs-thread/)。这里只补两条工程上的事实：

- 进程之间也可以共享内存，但要显式映射（`mmap` / `shm_open`），而且只共享那一块。车上传感器数据的零拷贝就是这样做的：共享的只有帧缓冲，其余内存仍然隔离。
- Linux 内核不区分两者：都是 `clone()`，标志决定共不共享地址空间。线程就是共享地址空间的“轻量进程”。

## Why do three models exist?

- **隔离要花钱。** 进程切换换页表，TLB 全失效。这笔钱买的是故障隔离。
- **内核介入要花钱。** 线程切换不换页表但要陷入内核，约一微秒。任务如果每干几微秒就等一次 IO，切换开销和干活一样多。协程把调度搬到用户态，切换变成一次函数调用。代价是内核不知道协程存在，一个不让出全体卡住。
- **多核要花钱。** 线程和进程能被分到不同的核。单个事件循环里的协程共用一个线程，所以协程擅长“很多任务都在等”，不擅长“几个任务都在算”。

值得试的组合：

- **线程、IO 密集**对比**协程、IO 密集**：时间线一样，差别全在切换成本和内存。IO 密集的服务用协程省的是这个，不是时间。
- **协程、CPU 密集、4 核**：只用一个核，而且没人能打断。大计算放进事件循环会卡住整个服务。
- **进程、崩溃**对比**线程、崩溃**：前者丢一个任务，后者全军覆没。

## How does a switch work?

```text
线程 A 正在跑
    │  时钟中断 / 系统调用 / 阻塞
    ▼
陷入内核
    保存 A 的寄存器
    调度器选出 B
    [进程切换才有] 换页表基址 → TLB 失效
    恢复 B 的寄存器
    ▼
线程 B 继续跑
```

协程切换跳过中间所有内核步骤：局部变量在堆上的帧里，暂停就是记下执行到哪一行，恢复就是跳回去。没有内核参与，也就没有抢占。

感知管线的分工：

```text
进程 A · 感知
    线程 1   camera 0 解码 + 预处理
    线程 2   camera 1 解码 + 预处理
    线程 3   送 GPU，等推理结果
    线程 4   日志写盘（事件循环，几百个文件句柄）
进程 B · 规划
进程 C · 控制
```

进程边界放在故障边界上，线程用来吃多核，协程用来吃等待。

## CUDA's "thread" is a different thing

GPU 也说“线程”，但三个问题的答案全变了。

- **谁调度：硬件。** kernel 的 block 被分到流式多处理器（SM），SM 把 block 切成 32 个线程一组的 **warp**。warp 才是调度单位：同一 warp 的 32 个线程每个周期执行同一条指令，处理不同数据。CUDA 的线程更像向量指令里的一条 lane。
- **切换多贵：零。** SM 上的寄存器文件装着几十个常驻 warp 的全部寄存器，切换只是换一个程序计数器。所以 GPU 藏延迟靠的是一个 warp 等显存时立刻发射另一个 warp，而不是像 CPU 那样靠 cache 和乱序执行。
- **一个线程出事：没有“一个线程”这回事。** 一个 `if` 让一半 lane 走 if、一半走 else，硬件用掩码把 warp 跑两遍。这叫 warp divergence。

<CudaThreadHierarchyViz />

| 问题 | CPU 线程 | CUDA 线程 |
| --- | --- | --- |
| 调度单位 | 单个线程 | 一个 warp（32 个） |
| 谁调度 | 内核软件 | SM 上的硬件调度器 |
| 切换成本 | 约 1 µs | 0 周期 |
| 藏延迟靠 | cache、乱序执行 | 大量常驻 warp 轮流发射 |
| 分支 | 各走各的 | 同一 warp 内发散就串行走两遍 |
| 适合 | 少量、逻辑各异的任务 | 海量、逻辑一致、数据不同的任务 |

“把循环搬到 GPU 上”的真实含义：每次迭代变成一个 lane，相邻迭代走同一条代码路径、访问相邻内存。做不到这两点，线程再多也没用。

## Trade-offs

- **进程**：隔离最好，切换最贵，通信要过内核。放在故障边界上。
- **线程**：共享最方便也最危险，能用多核。用于 CPU 密集的并行。
- **协程**：切换最便宜，内存最省，一个不让出全体卡死，用不了多核。用于大量等待的 IO。
- **CUDA 线程**：吞吐最高，但只在“同一段代码、不同数据、访存规整”时成立。

## Interview framing

“一帧 camera 数据从驱动到推理经过哪些执行单元？”可以这样答：驱动用 DMA 把帧写进共享内存，不经 CPU 拷贝；感知进程里一个线程拿到帧句柄做预处理，多路 camera 对应多个线程吃满多核；结果放进 pinned memory，一个线程送进 GPU，GPU 上数千个 lane 以 warp 为单位跑模型；推理结果通过进程间通信交给规划进程。每一步都能用“谁调度、切换多贵、出事连累谁”解释。

## Key ideas to remember

1. 三个问题分清三种模型：谁调度、切换多贵、崩了连累谁。
2. 进程是资源的容器，线程是执行的单位；Linux 里两者都是 `clone()`，差别只是共不共享地址空间。
3. 进程边界放在故障边界上，线程吃多核，协程吃等待。
4. CUDA 的线程是 warp 里的一条 lane，硬件按 warp 调度，切换零成本，靠常驻 warp 藏延迟。
5. GPU 上的分支发散让 warp 串行走两遍；分支和访存都要和 warp 对齐。
